# Hunk UI and feature audit

Audit date: 2026-09-19. Source: Hunk `9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a` (package version `0.22.0`). This is a source audit. No Hunk build, installation, interactive run, or benchmark was performed. Proposed scope is marked below; it is not a claim of completed work.

## Main finding

Build a new browser renderer around reusable review behavior. Do not translate terminal components one by one. Hunk already has a shared review document, store, actions, selectors, navigation intents, producer, broker, and HTTP/SSE surface. Its browser client is still absent at this revision. [Upstream status and phase plan, lines 3–12](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/docs/browser-review-rebuild.md#L3-L12).

There is a material unfinished boundary: HTTP publications expose position and resource metadata, but do not yet provide all live selection, filter, and note state needed by a browser. Upstream calls for bounded snapshot or delta transport. Therefore, attaching a browser is more than rendering existing JSON. [Open work, lines 46–50](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/docs/browser-review-seam-audit.md#L46-L50).

The user-approved interaction is one continuous review stream with all files in the sidebar. Selecting a file reveals it in the stream. Virtualization can limit mounted rows; it must not turn the product into a single-file viewer.

## UI ownership and Base UI map

Base UI supplies unstyled interaction components. Use StyleX to define their appearance. Base UI should own popup placement, focus behavior, dismiss behavior, and applicable keyboard semantics. It should not own repository state, review selection, search matching, or code geometry. [Base UI quick start](https://base-ui.com/react/overview/quick-start).

| UI part                                                                | Primitive                                                          | Application responsibility                                                                               |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| Application menus                                                      | Base UI `Menubar` and `Menu`                                       | Commands, enabled states, shortcut labels                                                                |
| Review toolbar                                                         | Base UI `Toolbar`; `ToggleGroup` for view choice where appropriate | Responsive auto/split/unified policy and persisted preference                                            |
| Searchable repository, branch, worktree, theme selection               | Base UI `Combobox`                                                 | Async loading, cancellation, stable IDs, preview/commit/cancel                                           |
| Small fixed option selector                                            | Base UI `Select`                                                   | Options and persisted value                                                                              |
| Help, settings, command palette shell                                  | Base UI `Dialog`                                                   | Content and command dispatch; palette search/list composition still needs app logic                      |
| Destructive note removal confirmation                                  | Base UI `AlertDialog` only if confirmation is desired              | The actual remove action and ownership checks                                                            |
| Path or line actions                                                   | Base UI `ContextMenu`                                              | Commands for the exact current target                                                                    |
| Anchored note controls and selection actions                           | Base UI `Popover` or `Toolbar`, as appropriate                     | Target identity and enabled commands; no alternate diff measurement system                               |
| Nonessential control descriptions                                      | Base UI `Tooltip`                                                  | Meaningful accessible names on controls remain required                                                  |
| Temporary success/failure message                                      | Base UI `Toast`                                                    | Error classification; persistent failures remain inline with a retry action                              |
| Notes input and settings fields                                        | Native `textarea`, Base UI `Field`/`Input` as useful               | Draft state, validation, save/retry policy                                                               |
| File tree                                                              | Pierre Trees                                                       | Canonical file order, filtered set, changed-file badges, reveal request                                  |
| Code, diff rows, line numbers, context, annotations and virtualization | Pierre Diffs browser components                                    | Source content, identities, note placement adapters, command coordination                                |
| Main panel split                                                       | CSS grid plus a small pointer/keyboard separator control           | Width bounds, persistence, accessible separator value; no resizable-layout library by default            |
| Find input, text, file counters and loading/error rows                 | Native HTML and minimal React components                           | Search scheduling and truthful status                                                                    |
| Main review scroll                                                     | Pierre's supported scroll/virtualization integration               | Stable anchor and reveal coordination; avoid a second virtualizer or wrapper that competes for scrolling |

Verified official component pages: [Menubar](https://base-ui.com/react/components/menubar), [Toolbar](https://base-ui.com/react/components/toolbar), [Combobox](https://base-ui.com/react/components/combobox). ## Semantics that a visual rewrite must retain

1. **Canonical order and identity.** Stream and sidebar use one ordered file set. Use stable file keys and content/source identities across refresh. Runtime row indexes and DOM IDs cannot identify notes or content. [Review type contract 1–10](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/packages/hunk/src/core/review/types.ts#L1-L10).
2. **Selection and reveal are distinct.** A selected hunk/file is semantic state. Scrolling is client-local behavior. Upstream navigation clamps ordinary file/hunk movement and wraps annotated-file movement. It also chooses whether to reveal a file header, hunk, or note. Preserve this policy until a deliberate product change. [Navigation 10–48](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/packages/hunk/src/core/review/navigation.ts#L10-L48).
3. **Filter and find are distinct.** Filtering changes the visible file set. Content find scans visible patch content, wraps results and lands on a matching line. Hunk advances once per matching hunk, not once per match. A desktop per-match find can be a later explicit change. Search is implemented as a bundled extension; dropping the extension system must not silently drop find. [Search contract 1–14](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/packages/hunk/src/extensions/default/ui/search/index.ts#L1-L14), [pure search 1–49](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/packages/hunk/src/extensions/default/ui/search/search.ts#L1-L49).
4. **Notes refer to source ranges.** A note has a side/line or old/new ranges, one owner hunk for rendering, and potentially several intersecting hunks for navigation. Do not regroup notes using only DOM containment. [Note targets 18–68](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/packages/hunk/src/core/review/types.ts#L18-L68).
5. **Copy selection is not comment selection.** A text drag can cross display decorations or files; a valid note target has stricter source-range rules. Native browser selection alone is not a complete semantic adapter. [Selection tests 496–957](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/packages/hunk/src/ui/components/panes/copySelection.test.ts#L496-L957).
6. **Refresh preserves reading position.** Capture a semantic line anchor and its viewport offset before layout or content changes. Reconcile it after the new document and geometry are ready. Existing terminal row anchors are a behavior reference, not reusable pixel math. [Anchor tests](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/packages/hunk/src/ui/lib/viewportAnchor.test.ts#L8-L90).
7. **Commands have execution boundaries.** Shared commands change review state; local commands change presentation; host commands run processes or reload sources. The browser must not expose every extension/host command automatically. [Command contract 10–26](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/packages/hunk/src/core/run/commandCatalog.ts#L10-L26).
8. **Multiple viewers need an explicit selection policy.** A user's scroll should not unexpectedly move another viewer. Upstream still records multi-client selection policy as open work. [Open policies 35–43](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/docs/browser-review-seam-audit.md#L35-L43).

## Theme boundary

Use Zed as a reference for density, typography, surface hierarchy, focus states, restrained borders, resizable panels, live theme preview, and coherent syntax/UI colors. Zed can preview themes while navigating a list and save on confirmation. [Zed themes](https://zed.dev/docs/themes).

Define application semantic colors through StyleX variables: surfaces, text, borders, focus, selection, additions, deletions, warnings and note colors. Supply the corresponding values through Pierre's supported theme interface. Portaled Base UI content must inherit the same theme; apply tokens at a shared ancestor such as the document root or a consistent portal container.

Do not claim that a Zed theme is a drop-in Shiki theme. Zed exposes named syntax captures and application colors. Shiki accepts its own theme input, including TextMate-style token rules. Importing Zed JSON requires an explicit mapping with defaults and documented lossy cases. Hunk's current theme adapter also has terminal dependencies (`ThemeMode` from OpenTUI and terminal color derivations). [Zed configuration](https://zed.dev/docs/themes#theme-overrides), [Shiki custom themes](https://shiki.style/guide/load-theme), [Hunk theme imports](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/packages/hunk/src/ui/themes.ts#L1-L16).

## Verification worth preserving

- Port pure review-conformance fixtures first: insertion/deletion edge cases, zero-count sides, gap expansion, note ownership, navigation wrap/clamp, removed/filtered selected files, publication ordering, and resource identity. Add the browser projection to the same fixture model. [Conformance consumers](https://github.com/modem-dev/hunk/tree/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/test/review-conformance).
- Translate terminal user-visible tests into browser tests rather than copying terminal snapshots. Verify find retention after reload, filtering exclusions, correct line reveal, and empty/missing search feedback. [Search integration tests 218–436](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/packages/hunk/src/ui/AppHost.search.test.tsx#L218-L436).
- Preserve watcher lifecycle cases: debounce, theme retention, sidecar reload, observer disposal, and late-event rejection. [Watch tests 59–195](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/packages/hunk/src/ui/AppHost.watch.test.tsx#L59-L195).
- Verify actual browser focus and scrolling: file jumps, hunk navigation, menu/dialog focus return, split/unified anchor retention, resize, virtualized text selection, note insertion, and source expansion above the viewport. Unit tests cannot prove those interactions.
- Keep explicit browser content-memory limits. A complete file list and scroll stream do not require every patch or highlighted model to stay resident.

## Reuse limitations and next audit gates

- Shared source modules are internal. The published package exports extension and OpenTUI facades, not a supported standalone headless review engine. Decide whether to maintain a fork, vendor a bounded set of modules, or cooperate on upstream extraction. Preserve the MIT notice with copied code. [Exports](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/packages/hunk/package.json#L34-L44), [license](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/LICENSE#L1-L13).
- The terminal renderer transforms Pierre output into custom terminal rows. Those row planners, Unicode-width measurements, custom scrollbars and cell selection controllers should not enter the browser bundle. [Row model boundary](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/packages/hunk/src/ui/diff/diffRows.ts#L1-L22).
- The existing SSE authentication requires a header. Use a streaming `fetch` reader, not native `EventSource`, if preserving this protocol. Reconnect receives a fresh publication rather than replayed deltas. [Transport requirements 19–29](https://github.com/modem-dev/hunk/blob/9b95a71b76c472bad21ffa5cc6b01b204e2f6f7a/docs/browser-review-seam-audit.md#L19-L29).
- This audit did not run package-boundary checks or extract/build shared modules. Browser safety, exact dependency closure, native runtime assumptions and Pierre API compatibility remain implementation-spike gates.
- “Hunk is good already” is a useful product reference, not a performance or correctness measurement. Record a baseline on representative repositories and compare the graphical implementation against explicit user-visible behavior.

Suggested review order: main finding → feature matrix → Base UI ownership → dependency retention → semantics and verification → reuse limitations.
